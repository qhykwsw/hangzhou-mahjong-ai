# 策略研究与 Agent 接口

## 长期策略与实验

策略按“研究方向 → 策略组合 → 独立分支 → 候选版本”组织。分支持续积累历史、最好版本、研究会话与迭代次数；实验记录本次对象、参数、执行任务和成绩，不拥有策略身份。新增实验不会清空已有分支。术语见 [CONTEXT.md](../../CONTEXT.md)，架构取舍见 [ADR-0006](../adr/0006-decouple-strategy-history-from-experiments.md)。

代码默认注册七种组合：三种风格启发式、自由规则策略、LightGBM、MLP 与 PPO；采样续打和多步蒙特卡洛树搜索保留注册能力，但不纳入默认研究组合。代码默认每个组合两条分支（DeepSeek、Qwen 各一条，共十四条）。当前自动研究项目 [research.toml](../../projects/agent-research/research.toml) 注册牌效优先、番型经营、局势自适应、自由规则四种启发式组合，每种一条 DeepSeek 分支（共四条），学习与搜索家族不参与本项目迭代。组合初版按需准备，只有被选中迭代的组合才启动初始化与训练。新组合由开发者通过配置和注册定义加入，网页不提供注册表单。组合可用 `branch_ids` 固定分支后缀，调整模型列表时不重排已有分支身份；移除的分支通过归档退出迭代与默认对比。

研究模型是分支属性，可以在结束当前实验后显式切换并保留变更历史。Astra 可选但不在默认注册分支中，默认 medium；DeepSeek 支持 low/high/max，默认 max；Qwen 使用 max。分支源码、模型和会话彼此独立；其他分支只共享公开成绩。

## 控制台与两阶段循环

```bash
.venv/bin/mahjong start
.venv/bin/mahjong status
.venv/bin/mahjong stop
```

启动打开控制台，不自动运行实验。实验参数集中在一处：轮数与每轮迭代次数、对比池 K、Agent 与 worker 并发、评估与训练场数、执行时限、进程内存与计算线程同组呈现，不再单独折叠。活跃分支以单一卡片列表呈现，宽屏每行三张、页面占视口宽度九成，每张卡片含组合、研究模型、当前最好版本、本轮对比版本、迭代与对比状态、训练选优与大乱斗进度，以及本分支正在执行的任务与最近动态；卡片同时显示该支现役版本的做法和最近一次研究判断（判断／方向／原因），详情对话框展示累计研究结论、适用条件与失败原因，并保留历次判断原文与候选历史。列表支持按策略组合与研究模型筛选、勾选；每轮迭代次数是全部选中分支共用的实验参数，单支额度覆盖只留配置入口，不在卡片上编辑。轮次级动态显示在阶段条下方，不另设全局任务与事件面板。

对比对象不再手动挑选：对比池自动取最近一次大乱斗前 K 名的参赛版本（尚无有效分支时用三种启动启发式），创建实验时固定，卡片以「对比对象」标记；勾选卡片只决定本轮迭代哪些分支，其余分支仍可参加轮末大乱斗。

**研究轮次**是一次完整的“迭代阶段 + 对比阶段”。**分支迭代**是一次提出候选、准备或训练、完整配对选优的尝试。一轮研究中每条选中分支可以迭代多次。代码默认十轮研究、每轮每支十次迭代；当前自动研究项目配置为 10 轮、每轮每支 3 次。两个参数独立；未选中的分支不增加迭代次数。

1. 迭代阶段固定本轮对比池。每场训练与选优比赛从池中均匀、有放回地抽取三个对手，允许重复版本，也允许本分支历史版本。训练和选优使用独立牌局与随机流。选中分支的每次迭代先整理尚未复盘的累计研究结论，再由 Agent 写下研究判断（对现役做法与轨迹的判断、本次方向、原因），再派生草稿和实现；没有判断就不能创建或提交候选。
2. 每次分支迭代默认提交一个候选，上限可配置为一至四个。全部准备成功的候选与原代表面对相同对手安排、牌局和座位，完成同等场数的完整比赛。选优主口径是完整结算的平均名次效用（4−名次，第 1、2、3、4 名依次为 3、2、1、0）。名次沿用线上赛段规则：非决赛按总分、名次分、白板获取数、稳定身份依次排序；只有每场产生的名次分在同分时取平均，不能把它混作最终赛段名次。决赛按总分并依规则加赛。场内 8 局的先后与落后时的激进打法不可交换。逐局读数（每局 4−局名次均值、每局得分均值）用满一场的全部 8 局作辅助，只用于观察波动与风格，不参与选优。同分保留原代表，候选都更差时继续保留原代表。
3. 单次分支迭代到达 `iteration_seconds` 上限时，未跑完的训练不再直接作废：执行器把最近一次已提交的检查点冻结成候选版本，照常参加同等条件的配对选优；只有完全没有检查点时才记为执行失败。冻结版本在卡片与进度中标为按检查点冻结，并按普通候选计入有效评估与提升统计。
4. 本轮选中分支完成各自额度后，进入对比阶段。所有未归档且完成过有效候选评估的分支各派一个最好版本进行大乱斗，包括本轮未迭代的分支。赛程均衡出场与四座轮换，尽量减少重复对手组合。
5. 大乱斗完整结束后固定排行榜，前 K 个代表成为下一轮对比对象。默认 K=4，最低为 1，不足时全选。自动进入下一研究轮次，直至总轮数完成。

初始对比池为保守、均衡、激进启发式各一个，不是基础 CLI 的 `rule` 策略。有实际分支完成有效候选评估后，启动策略退出常规池；未提升也可满足参评条件，全部执行失败不满足。大乱斗实际分支不足四个时，三种初始策略补位，必要时重复上场；补位策略不占实际分支前 K 名的名额。

新实验冻结的运行时发生变化时，生成对应的新启动策略版本，用于本实验的初始对手与补位。旧启动版本的源码、路径和运行时保留，不把旧观察协议的 worker 直接用于新协议。这不迁移或改写已冻结的分支候选。

没有提前筛选、动态追加评估样本、确认赛或自动淘汰。未进入前 K 的分支仍可迭代，也继续参加后续大乱斗。归档在结束实验后操作，收起分支且停止默认参评，历史版本保留；网页的分支卡片列表和排行榜隐藏归档分支，归档分支在「已归档分支」里按同样的卡片展示当前最好版本、迭代次数、最近迭代与累计提升，点「恢复分支」重新纳入对比池，可再被选作迭代对象和对手。

## 成绩、历史与恢复

实验与进度、全体排行榜是独立页面。轮内选优成绩附带实验与对手条件，不能直接混成全局实力排名。排行榜绑定实际参赛版本、研究模型与推理等级，支持查看历史对比记录；大乱斗尚未结束时标为临时排名。排名表达有限样本的表现，不计算 Elo。

轮内选优记录和排行榜同时提供标准误差与评估组数。主口径按四场轮换组（同副牌、同对手、四座轮换）先聚合出场均效用，再以组均值的样本标准差除以组数平方根估计标准误差，避免把同一组内的四场当作独立样本；不足两组时不估计。逐局效用与逐局得分均值（与平台总分口径一致）用满一场的 8 局，作为辅助读数一并展示。候选与基线共用同一份赛程，页面额外给出场口径的逐块配对差与标准误，用来判断本次选优是否落在噪声以内。这些数值描述本次读数的抽样波动，不是名次置信区间，也不参与代表选优或前 K 名筛选。

一次只运行一个实验，内部并发多个分支。暂停取消在途执行，继续时恢复已提交的训练检查点，并复用完整比赛回执，防止重复计分。服务重启后保留进度，须手动继续。「停止安排」有三种收工范围：本轮结束后；本次迭代结束后，各分支跑完当前这一拍、没在迭代的分支立即收工；立即结束当前迭代，取消在途任务并删除未完成的迭代记录与其草稿候选，分支回到就绪。三者都默认先跑完大乱斗再停，只有显式取消勾选才停在迭代阶段末尾、继续时再补大乱斗。安排不会被暂停或服务重启清掉，点「取消安排」才撤销，触发一次后自动清空；已完成迭代、现役代表和分支历史都不受影响。需要换对象或实验方式时，先用停止安排或直接暂停并等待结束，再点击“结束本次实验”；已完成的候选与分支历史保留，新实验从当前最好版本继续。

候选可以从本分支任意历史版本派生，但选优始终与本次迭代开始时的代表比较。有效评估、实际提升和执行失败分别统计。失败尝试消耗一次分支迭代额度；暂停不消耗额外额度，关闭未完成实验会结束当前尝试。

## 配置与资源

配置合并顺序为代码默认值、自动研究项目 [research.toml](../../projects/agent-research/research.toml)、创建实验时的网页设置。权威默认值和校验见 [config.py](../../src/mahjong_ai/research/config.py)。代码默认同时允许十四个研究 Agent、十二个训练 worker、十二个比赛 worker；当前自动研究项目为四个研究 Agent、十二个训练与比赛 worker。网页可设置候选数、训练场数、选优场数、大乱斗每支目标场数、单次迭代上限、初始版本训练上限、进程内存与计算线程。

当前自动研究项目候选训练额度为 16 场，轮内选优每版本 1024 场（8192 局），大乱斗每支目标 1024 场（8192 局），代码默认依次为 128、256、512 场。启发式分支没有训练槽，训练场数在纯启发式迭代里不消耗墙钟；选优与大乱斗的场数按 8 局一场折算成局数后，与逐局读数配套。`training_caps` 按组合家族限制训练额度：启发式与搜索家族为 0，即没有训练槽，`strategy.train` 会被运行检查拒绝，`research_submit_batch` 也不接受 `training_games`；规则策略的实测比较由配对选优完成，不必在训练槽里重打一批真实对局。value/PPO 保留训练槽，代码默认额度 128 场、上限 256 场，超限申请在运行检查之前就被拒绝。需要更大预算时改实验级配置，不由 Agent 单次提交决定。两项评估场数在实验开始时固定，不依据中途成绩动态追加。

配对选优按完整四座轮换组分片，每个参评版本分别产生任务。`evaluation_shards` 是期望分片数（默认 4），实际值还会按本批参评版本数（含原代表）与比赛 worker 数适配，并且不超过轮换组数；权威算法为 `research/service.py` 的 `evaluation_shard_count`。对手抽样、牌局与策略种子都由 `block` 决定，分片只改变任务切分，不增加样本、不改变任何一局；读数在分片到齐后合成，标准误仍按全部轮换组计算。实际并行度由可用 worker 和已就绪分片共同限制，不等于候选个数。

Agent 在下一次迭代提示中直接收到本分支上次的实际执行反馈，`research_status` 与 `research_history` 的各次迭代也提供 `execution_feedback`：申请训练场数、实际完成场数、参数更新数、研究 Agent 耗时、训练与准备耗时和单次执行上限。时间单位为秒，训练与准备耗时包括依赖准备、采集对局、训练和校验，排除排队与选优比赛；缺少记录的数值为 `null`。训练被时限打断而按检查点冻结的候选，`status` 为 `partial`、`interrupted` 说明原因、`completed_games` 为冻结时的实际场数。Agent 根据实际耗时、成绩及代码和对手变化自主调整后续训练场数，框架不自动放大或锁定场数。

| 设置 | 生效方式 |
| --- | --- |
| Agent、训练、比赛并发 | 后续调度，已运行任务继续 |
| 追加研究总轮数 | 当前实验继续推进 |
| 停止安排 | 本轮结束后、本次迭代结束后或立即结束当前迭代；默认先跑大乱斗，触发一次后自动清空 |
| 每轮分支迭代次数、对手选择与 K、训练与评估参数、家族训练额度、资源 | 新实验时冻结 |
| 对手池具体版本 | 按冻结规则在每轮大乱斗结束后更新 |
| 注册新组合、切换研究模型 | 通过配置与开发注册，结束当前实验后使用 |
| 框架、规则与动作窗口 | 新实验；旧版本仍使用其冻结运行时 |

单次分支迭代默认一小时，累计模型思考、依赖准备与训练的实际经过时间，不计排队、暂停和框架评估。到限时把最近一次已提交的训练检查点冻结成候选版本继续评估，该候选记为 `partial`；没有检查点的候选标为超时，全部失败则保留原代表。Agent 提交后立即结束回复、释放槽位；下一次分支迭代开新会话并携带结构化交接，不在旧会话上继续累积上下文。重复提交同一批次返回已接收结果。

执行器面向本机 CPU，macOS 使用 sandbox-exec，Linux/WSL2 使用 Bubblewrap 与 libseccomp。两者都限制文件访问、网络与候选派生进程，同时允许算法计算线程；沙箱不可用时拒绝执行，不回退到无隔离运行。依赖下载单独允许网络，创建依赖环境单独允许子进程，不把这些权限交给候选。每个候选受 RSS 内存上限和计算线程配置约束，Linux 统计沙箱启动器及其子进程的合计 RSS，超限明确报错，不替换设备或静默缩小算法。默认弃牌三秒、响应一秒，超时或非法动作由环境执行默认动作，完整结果照常计分并保留错误与回退统计。

模型配置从 `CODEX_HOME` 读取，未设置时使用 `~/.codex`。需要 `config.toml`；研究注册表里的 `deepseek` 与 `qwen` 分别叠加 `netease-deepseek-flash.config.toml`、`netease-qwen-flash.config.toml`。本机提供方配置和凭据不随仓库分发，变更后须实际调用验证。研究工具直接暴露，不依赖第三方模型工具发现能力。

模型网关会按账号限流，因此 Agent 任务每隔 5 秒放出一个，不把并发上限一次性压上去；网关返回 429、5xx 等瞬时错误时执行器按 30、90、180 秒退避重试，重试属于同一次任务，不消耗分支迭代配额。真正的失败（非瞬时错误或重试用尽）才把该次迭代记为失败。

研究 Agent 以 `--ignore-user-config` 启动，因此只继承显式转发的模型设置：`model`、`model_provider`、`model_reasoning_effort`、`model_catalog_json`，以及全局 `model_context_window` 与 `model_auto_compact_token_limit`（同时写进该次任务副本的 model catalog）。超过自动压缩阈值后由客户端摘要历史，作为长上下文的兜底。

**每次分支迭代开一条新会话**。上一轮对话归档到迭代记录上（`thread_id` 留档，仅用于审计），新任务携带现役代表、累计研究结论及待复盘证据、排行榜和上一次研究判断与执行反馈。累计结论跨实验保留，不按最近三次截断；不携带完整旧聊天或逐场回执，交接大小随研究记录增长。中途暂停后继续同一次迭代仍复用该次会话。

累计记录由 `research/conclusions.py` 根据已完成尝试投影，包含假设、Agent 的结论与适用条件，以及框架附加的候选/原代表、派生父代、对手池、玩法、样本量、配对差异和执行证据。结论分为已验证（`verified`）、已否定（`refuted`）、证据不足（`inconclusive`）、未有效验证（`untested`）。失败类型区分实现、资源限制、基础设施和原因未明；自检失败在修复成功后仍留档，没有提交候选的失败尝试也会进入记录。只有双方完成配置要求的完整配对评估且没有报错、超时或代打，才允许标记已验证或已否定；完整评估未提升不自动否定方向，仍需结合配对误差和适用条件判断。该门槛只保护研究结论，不改变选优计分。

下一次迭代必须先用 `research_record_conclusion` 整理所有 `assessment` 为空的记录，再声明研究计划。Agent 可以修订已有结论，旧记录保留，重复提交相同内容幂等；只能读写本分支的结论。最终一次迭代的证据会立即保留为待复盘，后续新研究再整理，不额外启动总结 Agent。详情页展示累计记录，完整修订历史在迭代记录中。

服务由 macOS 用户域 launchd 或 Linux/WSL2 的 systemd 用户服务管理，不注册登录启动项。macOS 保持 `ProcessType=Interactive`，避免候选进程被后台 QoS 降级；Linux 使用临时服务单元，停止时先通知主进程收尾，再清理剩余进程。改动服务安装方式后要重新核对比赛吞吐。优先端口 8765，冲突时选择可用端口；日志位于 `projects/agent-research/.local/service/service.log`，服务环境文件权限为 `0600`。`--no-open` 或 SSH 会话仅输出地址；WSL 优先通过 `wslview` 打开 Windows 默认浏览器，打开失败不影响服务启动。启动时若 WSL/Linux 内的 Tailscale 已连接，则同时监听回环与该 Tailscale IPv4 网卡；不把 Windows 宿主的 Tailscale 地址当成本机网卡。连接状态改变后重启服务。地址以 `status` 的 `url`、`tailscale_url` 为准。

### WSL2 环境

在 Ubuntu 内安装 `bubblewrap`、`libseccomp2`、`libgomp1` 和 `build-essential`，使用 Python 3.12+ 创建项目自己的 `.venv`。若默认 Python 版本较低，可使用 `uv venv --python 3.12 --seed .venv`。不要复制 Mac 的 `.venv`、wheel 缓存或 C 扩展；安装项目时在本机重新构建。

`systemctl --user show-environment` 必须能正常执行。若 WSL 尚未启用 systemd，在 `/etc/wsl.conf` 的 `[boot]` 节设置 `systemd=true`，再从 Windows 执行 `wsl --shutdown` 后重新进入发行版，见[微软说明](https://learn.microsoft.com/en-us/windows/wsl/systemd)。服务不依赖启动它的终端，但 systemd 服务本身不保证 WSL 实例持续存活；长时间研究需要保持实例运行。Windows 重启或关闭 WSL 后，重新运行 `mahjong start` 并在网页继续，不自动恢复实验执行。

## 候选契约与训练

权威契约为 [CONTRACT](../../src/mahjong_ai/research/contract.py) 与 [MCP schema](../../src/mahjong_ai/interfaces/mcp.py)。`strategy.py` 声明 `COMBINATION`，提供 `build(model_dir)`，返回实现 `reset(seed)`、`act(observation)`、`finish_round(result, seat)` 的对象。动作必须来自 `observation.legal_actions`。

研究契约直接提供杭州麻将的关键规则：仅自摸、没有点炮或抢杠胡，白板与吃牌限制，以及杠后爆头重算和补牌弃胡窗口。不能把其他麻将玩法的“安全牌/现物”当作本玩法的规则保证；弃牌仍可能帮助对手吃碰杠。`research_read_source("rules")` 提供判胡与番型源码，当前合法动作仍由观察决定。规则提示随新实验的运行时冻结，旧实验与已冻结候选不自动改写。

`research_read_source("observations")` 提供策略事件规范化和财飘判断。`Observation.base_score` 保留房间底分；`PublicEvent.concealed` 标记暗杠，非本人视角隐藏其牌面。策略事件不包含配牌、庄家初摸和网络 pass/timeout，局号按当前场从 1 开始，避免训练与线上使用不同的事件特征。吃碰后仍可能合法杠牌，吃前爆头、吃后弃白保持爆头也可财飘，均以合法动作与 SDK 判断为准。

value/PPO 组合的 `train(ctx)` 可生成模型或其他文件。`ctx.play(learner)` 请求一次真实完整结算，`ctx.play_many(learner, games)` 顺序采集轨迹。`ctx.episodes` 限制训练对局数，`ctx.output` 保存产物，`ctx.initial` 是派生父代模型；`ctx.checkpoint(metadata)` 原子提交恢复点，`ctx.completed_episodes` 和 `ctx.checkpoint_metadata` 提供恢复信息。启发式与搜索组合没有训练槽：`ctx.play` 只在训练上下文可用，把规则调参塞进训练槽会占用本支迭代时间，并且与随后的配对选优重复。

训练与策略只接收合法观察和清理后的结算。收益预测对实际动作记录真实回报，搜索估计标签另记来源。PPO 基线记录旧动作概率和价值，执行裁剪目标、多轮小批次更新与价值学习。假想模拟器从合法观察与独立随机流生成世界，不接收宿主真实隐藏状态。

候选须保持组合算法与指定决策侧重点或风格。牌效优先（`heuristic-efficiency` / `style=efficiency`）以向听、剩余有效进张和胡牌速度为主要依据；番型经营（`heuristic-fan` / `style=fan`）权衡速度与白板、爆头、财飘、杠的合法倍率收益；局势自适应（`heuristic-adaptive` / `style=adaptive`）根据公开分差、剩余局数与庄位动态调整速度和收益偏好。三者都不使用训练槽，仍按共同的终局名次目标评估。启发式对象提供对应 `style` 和 `utilities(observation)`；自由规则组合 `heuristic-unrestricted` 不限定攻守风格、不要求 `style` 字段，只要求规则／启发式决策和 `utilities(observation)`，允许按局面动态调整偏好；学习、搜索对象提供对应 `algorithm`，包装类也必须直接暴露。学习算法的 `train(ctx)` 与 `model/training.json` 必须证明实际更新。完整校验器通过 `research_read_source("capabilities")` 读取。依赖使用精确 `name==version`，下载 wheel 并安装到隔离环境；相同精确依赖环境可以只读复用。

每次迭代先整理待复盘结论，再写研究判断与代码：`research_declare_plan` 要求三个字段 `assessment`（现役策略现在具体做什么、这条分支的实测轨迹说明什么）、`direction`（本次要尝试的方向）、`reason`（为什么这个方向最值得做）。未声明判断时 `research_create_candidate` 与 `research_submit_batch` 都拒绝执行，Agent 必须在同一次回复里补上。判断按迭代保存，展示在网页卡片和详情里；上一次判断随执行反馈一起进入下一次迭代的提示，供 Agent 对照结果修正自己的判断。

工具回执可能丢失而调用已经生效，因此契约要求把报错当作状态问题处理：先重新读 `research_status`，按实际落到注册表的结果继续。`research_create_candidate` 对同一分支重复同名调用返回已有候选（`existing` 为 true）而不是报冲突，`research_declare_plan` 可安全重写；只有 `research_submit_batch` 需要确认结果，不能盲目重复。

草稿必须先跑通再提交：`research_check_candidate` 在冻结运行时里导入包、用完整校验器执行 `build`，有 `train` 时再打一场训练。`research_submit_batch` 会重跑同一套自检，失败就整批拒绝并返回原始错误，草稿保持可改、迭代仍为 researching，Agent 必须在同一次回复内修好重交；不能靠"写完就停"把跑不起来的代码送进准备阶段。通过自检的结果记在候选的 `preflight` 字段里；自检成败与原始错误另保存在 `checks` 中供累计复盘使用。

| 目的 | 工具 |
| --- | --- |
| 状态、历史与成绩 | `research_status`、`research_history` |
| 契约与公开 SDK | `research_read_source` |
| 整理累计结论、适用条件和失败原因 | `research_record_conclusion` |
| 迭代开始时声明研究判断 | `research_declare_plan` |
| 本支派生、读写 | `research_create_candidate`、`research_read_file`、`research_write_file` |
| 声明依赖 | `research_set_dependencies` |
| 提交前自检 | `research_check_candidate` |
| 提交后结束本轮会话 | `research_submit_batch` |

工具会话绑定当前实验和本分支；旧实验的会话不能修改新实验。研究 Agent 不控制评估条件、资源并发、用户轮数、选池规则或平台对战。

## 目录、备份与导出

- `projects/agent-research/.local/strategies/<combination>/<branch>/`：分支初版、草稿、冻结提交和准备完成的候选版本。组合下还保存共享初版与启动策略。
- `projects/agent-research/.local/research/`：实验配置与轮次回执、任务、按内容标识冻结的运行时、依赖环境、随机材料和 `reports/`。
- `projects/agent-research/.local/service/research.sqlite`：长期策略注册表、实验状态、事件和幂等回执。

三者一并备份才能完整恢复。框架代码在实验开始时冻结，候选引用自身的运行时，重启不会升级旧版本。按日期 run 划分的旧研究记录与旧研究协议都不迁移，也不建立兼容路径。

全新检出不包含历史实验、已训练模型或冻结发布包；首次打开控制台只初始化配置中的研究分支，历史和排行榜为空。运行数据均在本机生成且不纳入 Git。不同机器分别从新实验开始，不复制跨操作系统的运行时或继续旧机器的在途任务。

验收、吞吐与诊断记录保存到 `projects/agent-research/.local/research/reports/`，具体实验配置和轮次回执在 `projects/agent-research/.local/research/experiments/<id>/`。是否完成以完整任务和比赛回执为准，不能仅凭服务正常推断。

.venv/bin/mahjong-ai export --project projects/agent-research \

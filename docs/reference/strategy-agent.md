# 策略研究与 Agent 接口

## 研究对象

研究方向包含策略组合，组合包含独立研究分支，每支每轮提出一至四个候选。候选是参赛版本，分支是持续研究与淘汰的对象。完整术语见 [CONTEXT.md](../../CONTEXT.md)。

初始组合包括三种风险风格的精确牌形启发式、LightGBM 与 MLP 收益预测、前馈 PPO、采样续打与多步蒙特卡洛树搜索。同组合共享经过准备的初始基线，初始化不消耗迭代轮数；此后每支独立保存模型、源码与会话。

每组合默认三支，分别绑定一支 Astra、一支 DeepSeek 和一支 Qwen。Astra 默认 medium；DeepSeek 可选 low/high/max，默认 max；Qwen 使用 max。配置解析用户 `~/.codex/config.toml` 及对应 profile 文件，只传递研究所需的模型、提供方与模型目录设置。研究工具直接暴露，不依赖第三方模型的工具发现能力。前期模型绑定分支，后期在周期边界显式切换并记录历史。

## 启动与远程访问

```bash
.venv/bin/mahjong start
.venv/bin/mahjong status
.venv/bin/mahjong stop
```

`start` 打开控制台，不自动创建研究。网页中设置总迭代轮数与其他参数后创建；默认一百轮，到达目标后暂停，可以追加轮数再继续。每个项目最多运行一个研究。

服务优先使用 8765 端口，冲突时选择可用端口，以终端输出为准。`--no-open` 或 SSH 会话只输出地址。启动时 Tailscale 已连接，会同时监听回环和 Tailscale IPv4 网卡，`status` 显示 `url` 与 `tailscale_url`；后者为空表示没有远程监听。启动后才连接 Tailscale，需重启服务增加监听。

服务由 macOS 用户域 launchd 管理，不注册为登录启动项。服务日志位于 `.local/service/service.log`。停止服务会保留进度，重启后须手动继续。

## 迭代、评估与淘汰

每个周期冻结各分支的现役代表作为参照池，并为各支抽取覆盖不同组合的对手样本。周期内分支异步研究，达到终点后等待其他存活分支。

每轮现役代表和全部准备成功的候选，分别面对相同对手版本、初始牌局和座位安排，完成同等数量的比赛。每轮使用新牌局；没有提前筛选、动态追加或确认赛。完整结算第一至第四名分别得到效用 3、2、1、0，选择平均效用最大的版本，同分保留代表。

Agent 可从本支任意历史候选派生，评估仍比较现役代表。失败或没有提升都能给下一轮提供依据，不强制沿唯一父代链研究。排名只表达有限样本下的表现。

周期末每支派代表进行共同竞技，均衡出场、减少重复对手并轮换四座。共同竞技产生全局排行榜，周期内不插入额外比赛刷新排名。未完成时页面标为临时排名，完整结算后固定成绩，再淘汰。榜单按平均名次效用排序，展示组合、研究模型、推理等级和相对上个周期的名次变化；当前不计算 Elo，已淘汰分支从当前榜单隐藏。

默认首周期二十轮，之后每周期十轮。只检查末尾 `floor(N × 淘汰比例)` 支，默认比例 20%；从末位向前处理，若淘汰后组合少于最低保护数则跳过，不递补名额。默认每组合至少两支，并保持至少四支以继续四人比赛。达到保护下限时可以没有淘汰。总轮数终点落在周期中间，完成最终共同竞技但不额外淘汰。

## 资源、超时与恢复

Agent、候选准备/训练、比赛分别配置并发。Agent 提交后结束回复并释放槽位，框架确认提交后允许短暂收尾，随后释放槽位；评估后恢复原会话，不为每个分支永久占一个进程。重复提交相同批次返回已接收结果。

三类并发分别受模型网关、训练耗时和本机对局资源限制。调参时逐项增加，观察成功提交、训练完成、完整比赛与动作超时，不把快速失败计为有效吞吐。初始化基线可能面对简单内置对手，迭代训练则使用冻结参照池，初始化耗时不能直接外推整轮训练时间。网关限流、模型额度和 MCP 启动失败也可能消耗失败轮次，应先恢复服务能力再继续研究。

单次迭代执行上限默认一小时，累计模型思考、依赖准备与训练实际经过时间，排队、用户暂停和框架评估不计入。到期后成功准备的候选继续评估，其余标为超时；全部失败则保留代表。该次尝试消耗一轮，成功评估轮数与失败轮数分别展示。

暂停取消当前执行任务；续跑从已提交的模型检查点恢复，已完成的比赛回执不重复计分。明确的基线初始化失败会暂停研究，修正配置或环境后继续可重试。

当前执行器使用本机 CPU 和 macOS 强制沙箱。每个候选进程有可配置的 RSS 内存上限，计算库线程数按资源配置设置。超出资源时报错，不静默缩小算法或替换设备。Linux、远程 GPU 和 MPS 不属于当前执行器。

弃牌与响应窗口默认分别三秒、一秒，超时和非法动作采用环境默认动作，真实结果正常计分，错误与回退次数保留。响应超时过牌，自己回合能胡则胡，否则选择插入顺序末尾的合法弃牌；迟到回复不进入下一次决策。

## 配置

配置依次合并代码默认值、项目 [research.toml](../../research.toml) 和创建研究时的网页配置，完整默认值和校验见 [config.py](../../src/mahjong_ai/research/config.py)。网页完整配置编辑器可调整算法参数、模型目录配置、资源和自定义组合。

默认八个组合各有三条分支，初始共二十四条，每个组合的 `models` 为 `["astra", "deepseek", "qwen"]`。分支数决定持续探索谱系的数量，`candidate_limit` 决定单条分支每轮最多提交几个候选，两者独立配置。默认并发为十个研究 Agent、两个准备/训练 worker、四个比赛 worker；实验运行中临时调整的并发不会自动写回项目默认值。

模型配置从 `CODEX_HOME` 读取，未设置时使用 `~/.codex`。该目录需要 `config.toml`，默认 DeepSeek 和 Qwen 分别叠加 `netease-deepseek-flash.config.toml`、`netease-qwen-flash.config.toml`；其中配置真实提供方、模型及所需认证引用。`profile` 填不带 `.config.toml` 的名称。这些本机配置和凭据不随仓库分发，添加或更改提供方后须验证实际调用。

| 参数 | 生效时机 |
| --- | --- |
| Agent、训练与比赛并发，总轮数追加 | 后续调度 |
| 单次迭代上限、训练额度、候选上限、资源 | 下一迭代 |
| 评估场数、保护数量、淘汰比例、周期轮数 | 下一周期 |
| 新增组合/分支、研究模型切换 | 周期边界 |
| 麻将规则、结算和动作窗口 | 新研究 |

每个组合声明 `id`、`family`、`name`、`parameters`、`branches`、`models`，可选 `training_games`。`models` 列表长度必须等于分支数。可在四类现有算法家族中定义更多参数组合，新增算法家族需扩展基线与能力验证。修改配置不会改写已经启动的任务；界面显示待生效值。

每个研究保存创建时的配置和冻结运行时。修改项目默认值不会缩减已有研究的分支；现有研究只通过淘汰移除分支。需要从较小规模重新开始时，新建研究，保留原研究的记录与暂停状态。组合最低保留数量保护的是策略组合，并不保证每种研究模型始终有一条分支存活。

## 候选契约与训练

权威契约为 [CONTRACT](../../src/mahjong_ai/research/contract.py) 与 [MCP schema](../../src/mahjong_ai/interfaces/mcp.py)。`strategy.py` 声明 `COMBINATION`，提供 `build(model_dir)`，返回实现 `reset(seed)`、`act(observation)`、`finish_round(result, seat)` 的对象。动作必须来自 `observation.legal_actions`。

`train(ctx)` 可生成模型或其他文件。`ctx.play(learner)` 请求一次真实完整结算；`ctx.play_many(learner, games)` 顺序采集多局轨迹供批次更新。`ctx.episodes` 限制训练对局数，`ctx.output` 保存产物，`ctx.initial` 是派生父代模型；`ctx.checkpoint(metadata)` 原子提交恢复点，`ctx.completed_episodes` 与 `ctx.checkpoint_metadata` 提供恢复信息。

训练与策略只接收合法观察和清理后的结算。收益预测对实际执行动作记录真实回报，搜索估计标签另记来源。PPO 基线记录旧动作概率和价值，执行裁剪目标、多轮小批次更新与价值学习。公共假想模拟器仅从合法观察和独立随机流生成世界，不接收宿主真实隐藏状态。

组合算法与风格必须保持。启发式返回对象须提供对应 `style` 属性和 `utilities(observation)`；学习/搜索对象须提供对应 `algorithm` 属性，包装类也必须直接暴露这些属性，单独设置模块 `PARAMETERS` 不替代对象接口。完整校验器可通过 `research_read_source("capabilities")` 读取。候选准备检查组合身份、算法接口和训练产物，运行与测试检查合法性和算法行为。策略名或候选自报成绩不代替比赛证据。依赖使用精确 `name==version`，下载 wheel 并安装到隔离环境；同一研究中精确依赖相同的环境可只读复用，避免重复下载与安装，源码、模型、依赖指纹提交后冻结。

| 目的 | 工具 |
| --- | --- |
| 状态、历史与成绩 | `research_status`、`research_history` |
| 契约与公开 SDK | `research_read_source` |
| 本支派生、读写 | `research_create_candidate`、`research_read_file`、`research_write_file` |
| 声明依赖 | `research_set_dependencies` |
| 提交后结束本轮会话 | `research_submit_batch` |

本支全部历史可读；其他分支只共享公开成绩，不能读取其源码或模型。研究 Agent 不控制评估条件、资源并发、保护规则、用户轮数或平台对战。

## 目录与导出

研究状态保存于 `.local/service/research.sqlite`；`.local/runs/YYYYMMDD-research-NN/` 保存冻结 runtime、基线、分支工件、提交、作业与 `reports/`。两者一并备份才能完整恢复。旧研究记录不迁移，也不创建历史路径兼容链接。

后台与网页使用当前代码，研究任务使用创建 run 时冻结的代码。框架更新后新协议使用新研究，重启不会改写已冻结工件。

`reports/` 可保存独立的吞吐探针、监控、调参脚本和验收证据；这些是具体实验工件，不是默认后台服务的一部分。若某次实验另行注册了监控或自动恢复任务，整体暂停时须一并停止这些任务，再停止研究服务。端到端是否完成应以对应运行的完整比赛、周期和审计报告判断，不能仅凭服务正常或测试通过推断。

```bash
.venv/bin/mahjong-ai export --root .local/runs/<run-name> \
  --candidate <full-candidate-id> --output /path/to/bundle
```

导出冻结候选及对应 runtime，平台对战单独留存，成绩不回流研究训练。参见[平台接入](platform.md)。

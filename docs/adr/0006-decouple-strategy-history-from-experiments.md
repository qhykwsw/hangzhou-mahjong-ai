# 将策略长期历史与实验执行、对手选择和成绩展示解耦

此前研究以 run 和统一淘汰周期组织分支，无法直接表达只迭代部分策略、独立选择历史对手，以及不同策略累计不同迭代轮数的使用方式。策略按“组合 → 独立分支 → 不可变版本”长期积累，目录以组合组织，研究模型作为可显式切换且保留历史的分支属性；实验只关联所选对象及执行记录，不再拥有策略的长期身份，并支持后续注册新组合。

前端以单一分支卡片列表呈现全部活跃分支，每张卡片含组合、模型、当前代表、对比版本、实时进度以及本分支正在执行的任务和最近动态，支持按策略与研究模型筛选。实验轮数、并发、worker、评估与训练等参数集中在同一组输入中，轮次级动态贴在阶段条下方，不另设全局任务与事件面板。勾选卡片决定迭代对象，对手池不由用户挑选而按规则自动生成；对手池作为所有迭代对象判断进步的共同锚点，每场比赛从池中版本有放回抽取三个对手，允许重复版本和本分支历史版本，不采用先按组合、分支再抽历史版本的方式。

默认取排名的前 4 个版本作为对比对象，数量可配置且最低为 1，不足时全选；没有历史排名时按分支代表的稳定顺序补足。分支至少完成一次有效候选评估后才进入参评范围，不要求新候选一定超过初版；全部执行失败不满足条件。尚无符合条件的实际分支时，启动池固定为保守、均衡、激进三种启发式各一个；存在实际分支后，三个启动策略退出常规对比对象，不为凑足 K 个版本重新加入。启动策略与实际启发式研究分支各自的初版代表分别记录身份。

候选训练和轮内选优共用本轮固定对手池，均允许有放回抽取对手，不增加单独的训练对手选择器。训练、选优评估和轮末共同竞技使用独立牌局与随机流；只有训练过程更新对局策略模型，评估使用冻结版本。研究 Agent 可读取清理后的评估结果，不能取得宿主真实隐藏牌或评估随机材料。

研究轮次分为两个阶段。迭代阶段固定本轮对手池，只有选中的分支各自执行指定次数的分支迭代，每场从池中随机、有放回地抽取对手。对比阶段由所有仍参与研究且符合参评条件的分支各派一个现役代表进行大乱斗，包括本轮没有迭代的分支；这是代表之间的共同竞技，不是仅让新代表再对旧锚点池打分。该阶段形成统一排名，前 K 名成为下一研究轮次的默认对比对象。

大乱斗预期至少有四个实际分支；不足时统一使用三种初始启发式策略补位，需要时允许重复上场，仍执行正常比赛与计分，不增加单分支免赛等特殊流程。补位策略不成为实际研究分支，不占实际分支前 K 名的名额。这是实际策略出现后初始策略退出规则的补位例外。

每次分支迭代让原代表与准备成功的候选按相同条件参评。候选晋级先满足[研究手册的证据门槛](../reference/strategy-agent.md#成绩历史与恢复)，再从达标候选中选取均值最高者；无人达标时保留原代表。此前只比较均值的结果仍按各自冻结运行时保留。候选冻结前必须在冻结运行时里跑通：提交时执行导入、`build` 能力校验及对应家族的实跑自检，失败则整批拒绝并回传原始错误，草稿保持可改。完整比赛终局名次对应的 3、2、1、0 平均效用用于选优与排名，不另建随对手条件变化的代表集合。有效完成评估、实际提升和执行失败分别表达，未提升不等于执行失败。实验成绩附带对手与评估条件，排行榜绑定实际参赛版本，并保留历史榜单，新版本不继承旧版本成绩。

取消全局自动淘汰，不要求所有注册分支都迭代相同次数；每轮只等待本轮选中的迭代对象完成其额度，再进入全体符合条件分支的对比阶段。用户可选择继续迭代或归档，归档分支保留历史版本但退出自动对比池。单次迭代达到执行时限时冻结最近一次训练检查点作为候选照常参评，只有完全没有检查点才记为执行失败。一次仅运行一个实验，内部并发迭代选定分支；不实现多个实验并行。保留实验配置、版本引用、执行回执与恢复所需记录，取消以日期 run 划分策略历史的方式。

界面分别配置实验总研究轮数和每个研究轮次内的分支迭代次数，后者允许单支覆盖；自动重复“迭代阶段 → 对比阶段 → 更新对手池”，直到总研究轮数完成，每轮均选前 K 名。分支累计迭代次数跨实验保留，失败尝试消耗分支迭代额度。运行中可调整并发、追加总轮数和暂停继续；初始对手选择、选池规则、评估条件、算法训练配置与运行框架在实验开始时冻结，对手版本按既定规则在研究轮次边界更新。用户主动改变上述实验条件另开实验。新增组合由开发协作修改注册定义，不实现网页注册表单。

不为旧研究协议增加迁移或兼容层；已冻结的候选、运行时和回执继续保留，框架协议变化通过新实验生效。以上设计已实施于长期注册表、两阶段调度与控制台，同步取代 ADR-0002 中的保护淘汰、ADR-0003/0004 中的全体分支等额迭代与淘汰周期约束以及 ADR-0005 中的周期边界切换约束，现行操作见[研究手册](../reference/strategy-agent.md)，具体测试与验收证据保存在 `projects/agent-research/.local/research/reports/`。

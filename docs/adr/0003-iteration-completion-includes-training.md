# 以完成迭代工作衡量进度，包含候选所需训练

研究按迭代轮数推进，候选需要训练时，完成训练是该次迭代完成的必要条件。启发式修改权重与 PPO 修改后完成训练可以各算一次迭代，不要求两者耗时或算力相等，也不因为当前运行机器是 Mac 而预先压缩到小型算法规模。

接受不同研究分支吞吐不一致的代价，以支持适合麻将任务的算法探索规模。分支间采用周期内异步推进、周期末统一结算，见 ADR-0004；研究不以统一墙钟预算截止，不等同于取消对局动作窗口或失联检测。

单次迭代初始设置一小时可配置上限，累计研究和候选准备实际经过的时间，包含模型思考、依赖准备与训练，不包含资源排队、用户暂停和框架评估；并行执行不叠加 CPU 时间。超时后已准备成功的候选继续完整评估，其余标记超时；全部失败则保留现役代表。该次尝试消耗一个迭代轮次，同时分别记录成功评估轮数与失败轮数，下一轮可依据错误与检查点修正。该上限约束单次尝试，不替代研究总轮数。

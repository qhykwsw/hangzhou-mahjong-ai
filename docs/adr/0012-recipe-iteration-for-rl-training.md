# 用训练方案迭代改进模仿之后的强化学习

2026-09-21 决定。方案迭代独立评估、独立大乱斗与四个固定规则对手的部分，已由 [ADR-0013](0013-unified-research-branches-and-common-brawl.md) 取代：方案分支并入研究框架，由研究框架评估，训练对手默认为评估对手。

[ADR-0011](0011-rule-guided-policy-learning.md) 的模仿启动已经确定：纯模仿约 40 分钟后到达平台期。之后的 PPO 加教师辅助没有稳定增益，第 1 轮超参数筛选也在约 1.6 小时时叫停。叫停后的诊断说明，问题出在训练方法本身，调参数解决不了（见下文“起点诊断”）。因此不直接进入 ADR-0011 设想的约一周正式主训练，改为做“训练方案迭代”，口语也叫“强化学习自迭代”：研究模型提出训练方案的修改，框架限时训练并做配对评估，研究模型根据结果再改下一版。

这里的“自迭代”指研究模型的改进闭环，不是策略和自身旧版本对弈。它借鉴 `~/code/autoresearch`：固定评测，每次实验限时，由 Agent 改代码。它和规则自迭代分开运行：迭代频率不同、改进对象不同、评估方式也不同。规则自迭代的四个分支代表在这里用作冻结对手，教师是规则冠军。

## 决定

### 改进对象与固定条件

- **改进对象**：一个训练方案，即名为 `recipe` 的 Python 包，框架调用 `recipe.train(ctx)`。方案可以改：
  - 采集方式；
  - 优势与回报；
  - Critic 的结构和输入；
  - 损失、优化器、教师约束；
  - 对手构成、探索方式和时间分配。

  接口见 [recipes/API.md](../../projects/personal/selfplay/recipes/API.md)，基线方案见 `recipes/baseline/recipe/`。
- **固定、方案不能改的部分**：
  - Actor 结构与观察编码；
  - 游戏环境与桌面分奖励；
  - 冻结对手与教师；
  - 训练时限，以及显存与内存上限：显存按方案线配置的比例封顶，超出时进程内报 CUDA 内存不足，不溢出到共享内存；训练进程组内存超限时整组结束，两者都记为训练失败，不影响主机；
  - 评估与晋级规则；
  - 每条方案线的固定起点。

  这些由冻结的框架快照 `guided/trial.py` 执行。Agent 能读到框架源码，但不能修改。
- **隐藏信息的边界**：Critic 和训练目标可以读完整的隐藏状态，包括对手手牌和按摸牌顺序排列的牌墙，通过 `critic_features` 钩子在对局进程内取得。Actor 只读合法观察，评估时不调用任何钩子。这沿用 ADR-0009 的训练期例外。

### 一次方案尝试

1. **研究模型设计方案**：每次尝试开一个新会话，携带结构化交接，包括累计结论、现役方案、晋级曲线，以及上次尝试的训练诊断与评估。研究模型的流程：
   1. 先复盘已完成的尝试，写下累计结论；
   2. 再写研究判断（现状、方向、原因）；
   3. 修改工作区；
   4. 在目标主机上冒烟实跑；
   5. 冒烟通过后提交。

   思考时限 5 分钟；冒烟在远端运行的时间另行补偿，最多补偿 3 次。时限内没有提交的尝试记为“未提交”，照样消耗一次额度。
2. **限时训练**：从方案线的固定起点训练 2 小时（2026-09-23 起，见“基线方案与训练时长”）。超过 2 分钟宽限后强制结束进程，只保留方案最后一次 `ctx.save_actor` 的权重。
3. **配对评估**：训练出的 Actor 与现役 Actor 在同样的牌墙、座位和冻结对手上各打 4096 场，四座配对差的 95% 区间下界大于 0 才晋级。晋级条件与规则自迭代一致，场数不同（原因见下一段）。每次尝试换一组新的评估牌墙，避免反复在同一批牌局上挑选。

   场数最初沿用规则侧的 1024 场，第 1 次尝试后改为 4096 场（2026-09-21）。两边场数相同时，精度差很多：
   - 规则候选通常只改一条规则，同牌墙、同座位下 84%～87% 的四场组打法完全一样，新旧版本分组得分的相关系数约 0.98，1024 场的区间半宽约 ±0.5 分。
   - 限时训练会改动 Actor 的全部参数，几乎每场都有决策翻转；牌局一旦走岔，摸牌顺序就错位，配对相关系数只有约 0.63，1024 场的区间半宽约 ±2.6 分。这意味着单次尝试要接近一步追平规则冠军才可能晋级。
   - 4096 场把半宽降到约 ±1.3 分，每次尝试多用约 10 分钟评估；按每小时能确认的晋级数算，它比 1024 场和 2048 场都多。
4. **大乱斗**：晋级后串行跑一次五方大乱斗，参赛方是现役模型加四个规则对手，每方 1024 场，全部跑完才开始下一次尝试。方案线的起点先跑一次，作为第 0 点。同一方案线的各次大乱斗使用同一组牌墙，这些点连成晋级曲线。

没有训练产物、训练报错或超时的尝试都消耗额度，结果按“未晋级 / 训练失败 / 未提交”分别统计。SSH 中断、远端进程丢失这类基础设施故障自动重试两次，仍失败就暂停实验，不消耗额度。

### 方案线与编排

- **两条方案线**：
  - 4090 跑大模型 384/8/8；
  - 4070 跑小模型 256/6/8。

  两条线各自以“40 分钟模仿 + 20 分钟低学习率纯模仿”的模仿平台快照为固定起点。第 0 版的现役模型是基线方案从起点训练一个时限的产物：基线本身能提升，新方案要和它在同样时长里比。两条线各自有现役方案、结论和曲线，互不读取对方的历史。每条线严格串行，两条线之间并行。
- **首次尝试**：由研究模型在基线方案 `recipes/baseline/recipe/` 上修改。
- **编排器**：轻量编排器 `src/mahjong_ai/recipes/` 负责：
  - 尝试的生命周期与晋级判定；
  - 独立状态库 `projects/personal/selfplay/.local/recipes/recipes.sqlite`。

  它和规则研究运行在同一个工作台服务进程里，状态分开存放。每次尝试调用一次研究模型会话，复用规则研究的会话执行器，只换成方案专用的 MCP（`recipes/mcp.py`）。远端训练、评估和大乱斗由 `guided/recipe_jobs.py` 分离运行并轮询，服务重启后可以重新接上。研究模型默认 deepseek，可在 `recipes/iteration.toml` 中更换。
- **控制与额度**：不设轮次，每条方案线有尝试次数上限，可以追加。控制与规则自迭代一致：
  - 暂停、继续；
  - 当前尝试后停；
  - 立即结束当前尝试：丢弃进行中的尝试、不计次数，并终止远端进程；
  - 追加次数；
  - 结束实验。

  工作台的“训练方案迭代”标签页显示两条线的进度、当前计划、晋级曲线、尝试记录与累计结论。
- **冻结**：每个实验冻结四项内容：
  - 框架源码快照；
  - 当时的规则代表与冠军；
  - 固定条件；
  - 起点权重。

  规则侧之后的晋级不会同步进进行中的实验；换对手或改框架时新建实验。

## 基线方案与训练时长

2026-09-23 更换基线，依据是 2026-09-22 的小模型多向探索，逐项记录见本机 `projects/personal/selfplay/.local/recipes/rl-exploration-20260922/`。

- **旧基线测不出强化学习的效果。** 在起点上，教师交叉熵梯度的信号范数平方约为策略梯度的 100 倍，两者方向几乎正交，λ=1 时约九成更新在继续已到平台的模仿。每步只有约 2 万行，而策略梯度的噪声尺度约 70 万～230 万行。
- **新基线：多步小步策略梯度。** 每一步：
  - 用当前 Actor 采约 60 万个决策，不要教师标签；
  - 回报是本局剩余得分，下一局轮到自己坐庄时再加上本批数据测得的坐庄溢价；
  - Critic 在另一半对局上拟合，作为基线；
  - 不走步地累积全量策略梯度，再把步长缩放到 KL(当前‖新) = 0.03。
- **为什么是小步、大批量。** 同样步长下，策略梯度方向比随机方向好约 2 分，但方向里的噪声会造成同量级的损害：单步走到 KL 0.1 以上、连续大步、每步 KL 0.06，结果都更差。每步 KL 0.03 的轨迹前两步略降，约第 6 步起稳定转正，第 11～14 步 +1.6～+2.5（4090 小模型，每边 4096 场，每个点区间下界都大于 0）；第 14 步每边 16384 场复核为 +1.56 [+0.90, +2.23]。正式基线从起点训练 2 小时，每边 16384 场评估：4070 两个种子 +0.94 [+0.13, +1.75]（12 步）与 +1.58 [+0.85, +2.30]（11 步），4090 +0.83 [+0.10, +1.55]（8 步）。单次训练的种子波动约 0.3～0.45 分，与评估标准误同量级，第 0 版只训练一次，新方案约需高出 1 分才能确认。
- **训练时长 2 小时。** 4070 每步约 10 分钟（采样约 400 秒），4090 约 14～15 分钟（采样约 700 秒，大小模型相近），2 小时分别约 12 步和 8 步。30 分钟只有 2～3 步，正落在“先略降”的区间。4090 受 CPU 限制（20 线程），采样进程从 16 个加到 20 个只快约 6%。
- **评估。** 两小时内新旧方案的差异通常在 1 分以内，每边 4096 场的标准误约 0.5～0.7 分。建议改为两段式评估（4096 → 16384 场），这一项另行确认。

## 起点诊断

以下是研究模型每次尝试都会读到的事实，测于 2026-09-21 至 09-23，小模型，起点为模仿平台快照。详细数据在本机 `projects/personal/selfplay/.local/reports/20260921-rl-diagnosis/` 与 `projects/personal/selfplay/.local/recipes/rl-exploration-20260922/`。

- **一局的结果大多是运气。** 本局剩余得分的标准差约 13～15 分。Critic 在决策时刻的留出 R² 只有约 0.2；再给它看对手手牌、按顺序的后 16 张摸牌、人工“手气”特征，也到不了 0.23。oracle 输入能认出是哪一局，第二遍训练就开始背结果、变差。整场剩余得分的 R² 为负。
- **策略梯度的方向是真的，但极弱。** 噪声方差等于信号时的批量约 70 万～230 万个决策。同样 KL 下，策略梯度方向比随机方向好约 2 分；随机方向本身在 KL 0.1 时就要亏约 1.5 分。
- **教师项会盖过强化学习。** 教师交叉熵梯度的信号范数平方约为策略梯度的 100 倍，方向几乎正交；模仿已到平台，沿模仿方向走 KL 0.03 只有 +0.14。
- **起点策略很尖。** 熵约 0.08。能自摸时和 80%，另 20% 放弃继续打；这类和不和的决策改变后，一整场可能差 10 分以上。
- **坐庄溢价为正。** 本起点坐庄那一局平均比不坐庄高约 0.7 分，比每局约 13 分的噪声小得多。
- **学生每局比教师低约 3 分。** 按推演估计，主要来自每局约 2 次与教师不同的出牌，每次约 −3 分；教师选择吃时学生多半不吃，这反而略好。放大这些样本的模仿权重，30 分钟无可测提升。
- **已排除的方向**，结果均为对起点，每边 4096 场：
  - 小批量 PPO 加教师项，2 小时无趋势；
  - 单步走到 KL ≥ 0.2，−2～−7；
  - 连续大步、每步 KL 0.06：越走越差；
  - 所有批次梯度平均后从起点走一步：学成“能和就和”，−12；
  - 整场回报或局末 Critic 自举：不如按局回报；
  - 优势截断、取符号、排名变换：信噪比没有稳定提高；
  - ε 探索：行为策略与学习策略差太多，KL 约束下一步都走不了；
  - 同牌墙反事实推演：换一张牌，后续摸牌和吃碰全变，差值和换一副牌墙一样嘈杂。
- **基线的节奏。** 每步：4070 约 10 分钟，其中采样约 400 秒；4090 约 13 分钟，其中采样约 700 秒。前两步略降，约第 6 步起稳定转正。

## 考虑过的替代方案

- **直接做约一周的正式主训练**：在方法本身有问题时，拉长训练时间只会浪费预算。
- **只做超参数搜索**：诊断出的问题是回报定义、Critic 可见信息和探索不足，都在超参数之外。
- **先做“学习率 1e-5 纯模仿”的退火对照**：用户认为当前重点是强化学习本身，暂不做。
- **放弃强化学习，只用模仿**：用户明确拒绝。目标是一个能稳定提升的强化学习框架。
- **合并进规则自迭代的研究分支**：两者迭代频率和评估方式不同，合并会让两边的状态机都变复杂；只复用会话执行器、工作台和冻结对手。
- **沿用规则侧的 1024 场配对评估**：见上文，强化学习的新旧模型配对降噪有限，1024 场只能分辨约 2.6 分以上的进步。
- **两条线共享结论**：用户选择各自独立，避免一条线的结论在另一种模型规模上被当成已验证。
- **固定六方大乱斗（起点 + 现役 + 四规则）**：用户选择五方。起点已经是第 0 点，之后只比较当次的现役模型。

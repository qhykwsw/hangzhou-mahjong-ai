# Mac 总控容忍远程主机掉线，分支随时加入，网页只读

2026-09-23 决定。补充 [ADR-0013](0013-unified-research-branches-and-common-brawl.md)。

统一研究分支之后，调度依赖三台机器：任一远程主机失联或重启，评估任务失败就会暂停整个实验，和那台主机无关的规则分支也会停下。迭代分支在建实验时选定，中途不能增减。网页还保留着手动建实验和改参数的表单，但用户实际只通过对话来调整。改为：

- **Mac 是唯一总控，远程掉线不影响本机的规则迭代**：主机连续 10 分钟探测失败即视为离线。方案分支所在主机离线时，该分支不开新迭代、不预先设计（评估对手在迭代开始时冻结，干等会过时），现役模型照常参赛与当评估对手；在途工作等主机回来接着做。溢出的规则评估迁回本机。
- **大乱斗排空**：大乱斗主机离线且大乱斗到期时，本机停止开新迭代，等本机进行中的迭代跑完后在本机跑大乱斗，结束后恢复迭代。场数不打折，因为评测条件不能为了省时间而改；这段时间本机的规则迭代暂停。排空期间主机恢复，且大乱斗尚未开跑，就改回主机。主机中途掉线时，已取回的分片保留，缺失分片按本机大小补跑。模型座位在 MPS fp16 与 CUDA fp32 上接近平局时可能选择不同，视为同一评测条件（Mac 上的规则评估早已如此）。
- **主机故障不归咎候选**：主机重启导致工作丢失、主机不可达导致启动失败，都不消耗迭代次数、不计失败，工作在主机恢复后重做。判断重启的依据是主机开机时间晚于任务启动时间；进程无回执退出而主机没有重启，仍记为失败。
- **暂停与重启**：暂停只停止开新工作，远程评估、大乱斗与方案训练继续跑，继续后认领结果。Mac 重启后实验保持暂停，由用户决定何时继续，不自动继续；本机被打断的任务从头重跑，远程任务按启动记录重新认领。
- **迭代与参赛解耦**：分支有迭代中、仅参赛、归档三种状态，参赛的总是现役代表。分支阵容、分支状态、研究模型、固定参赛者与主机分工以 `research.toml` 为唯一来源，后台检测到变化即应用到运行中的实验；评估条件与计分相关的键运行中改动一律拒绝，只能随新实验冻结。新进入大乱斗的参赛者计一次待定晋级，沿用 4 次与 12 小时兜底的触发规则。
- **网页只读**：去掉所有表单与按钮，增加主机状态；实验的建立与暂停、继续、停止安排、结束，改由 `mahjong create` / `mahjong control` 执行，用户通过对话让 Agent 操作。

## Consequences

- 配置文件从“新实验的参数”变为运行中实验的活动控制面；运行中的配置错误只记在状态里并显示，不中断实验。
- 本机大乱斗期间规则迭代全部暂停，4090 长时间离线时，这类暂停会随每次大乱斗重复出现。
- 训练方案服务的远程作业在主机不可达时无限期等待，不再按固定重试次数判失败。

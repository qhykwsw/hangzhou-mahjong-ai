# 规则研究为独立对局策略训练提供教师

2026-09-20 决定，2026-09-21 按启动方式对照、纯模仿时长曲线、两轮大乱斗与 4070 推理实测修订。

[ADR-0009](0009-independent-selfplay-trainer-for-personal-project.md) 的纯自我对弈路线训练四十多小时后仍弱于规则研究的成熟策略。规则研究继续维护多条研究分支及冻结候选，人工项目 `projects/personal/selfplay/` 另建一条训练路线 `guided/`，消费其中可追溯的具体版本作为教师：先复用规则能力，省去从随机策略重新探索的成本，再按真实结算得分寻求超越教师。该路线不兼容旧 RL 模型与训练状态，目标是在多种强对手条件下的期望桌面分。现役代表只表示其分支在相应评估条件下保留的版本，不等于跨条件的绝对最强策略。

## 决定

### 教师与对手

- 主要模仿 Mac 最近一次完整共同评测中的规则冠军，不把四路规则等权混成监督教师。冠军取指定四个规则分支在完成榜单中的最高排名，使用该次实际参赛的冻结候选版本；不读取临时排名，也不把任意单分支晋级当作冠军变更。其他成熟规则作为训练对手。
- 信任 Mac 的共同评测选师结果，台式机不重复做教师棋力选优，只验证冻结包完整性与目标机运行正确性。接收、运行校验与启用分开记录，不能运行的新包不替换现役教师。
- 新冠军同步并通过运行校验后，在下一次例行评估中与冻结学生比较，再随下一评估代启用；不因新版本到达而打断训练，也不重新审核 Mac 的冠军选拔。换教师后渐进替换：最新教师的示范占主导，保留小比例、容量固定的旧示范，数据关联各自的冻结教师版本。
- 内置启发式退出主训练和主要棋力评估，只留在冒烟测试与故障排查中。训练对手持续吸收成熟规则更新与本路 RL 历史快照；评估面板在一个实验内固定，升级评估难度时建立新的评估版本并分开记录成绩曲线。

### 训练流程

- 先纯模仿，再联合训练。纯模仿阶段只用教师标签更新 Actor，按时长结束，不设棋力验收门槛，也不做价值预训练。联合训练中学生生成实际对局轨迹，教师在学生访问的合法观察上标注；PPO 只用学生自己的行为与概率，教师标签只进入监督损失，教师代打的样本不冒充 on-policy 数据。Critic 在联合训练中学习，不另设预训练阶段。这一条取代原先“统一训练循环、不设模仿阶段”的设想，依据见下文启动方式对照。
- 教师指导强度由各代学生与当前规则冠军的评估差距决定，不按时间或样本数衰减。学生和教师分别面对同一批对手、牌墙与座位，以四座配对组估计场均桌面分差 `d = 教师 − 学生`，记 95% 配对区间半宽为 `u`，取 `w = clip((d + u) / D, 0, 1)`，教师损失系数为 `lambda_max * w`，PPO 始终保留。`d + u <= 0` 时关闭模仿；均值领先但证据不足时保留少量指导；学生重新落后时指导可以加强。首次评估前 `w = 1`，这是初始化假设。该区间用于训练控制，不代表多次查看后的总体误判率保证。
- 训练按评估代推进：训练若干批次、冻结学生、完成师生配对评估、计算指导强度，再继续训练。评估开销目标约占总计算时间的一成；最终测试集不参与控制循环。
- 保存最佳已评估版本，允许训练中的正常棋力波动，不因一般退步自动回滚；数值异常、非法动作等执行故障单独处理。
- Actor 只读合法观察及本手公开历史，保留精确向听、有效进张等可合法计算的特征。Critic 独立参数与优化器，额外读取三家手牌与牌墙构成，用原始分数期望的标量输出加 PopArt 归一化，取代旧路线用 symlog 均值反变换充当期望的做法；Critic 只在训练进程内使用，不随 Actor 发布。奖励是每局收支除以底分，整场之和等于桌面分，不加向听塑形，不裁剪。
- 所有实验都是有限任务，结束后不自动进入下一阶段。正式主训练的预算与起止时间在启动时确定；约一周是用户的预算意向，尚未安排。

### 机器与部署

- 4090（`gpu-4090-wsl`）承担主要训练、规模试验与离线评估；4070（`gpu-4070-wsl`）是正式内网比赛推理的唯一目标，因为比赛在内网进行，4070 延迟最小。4070 曾在规模训练中崩溃，用户要求此后不在其上跑大模型规模训练或显存压力探针；小模型训练与评估经用户授权可以进行。
- 两机各自训练，不做跨机梯度同步或共享 PPO 轨迹，只交换经完整性校验的冻结源码、教师包、检查点与评估回执。同规模的方法比较在同一台机器、同等端到端预算下进行；跨机器分数只用于选优，不单独归因于模型规模或方法。
- 模型规模按目标主机实测选择，不预先锁定最小模型，也不以显存能放下的最大模型为目标。选型和发布验收必须包含 4070 实机的显存、吞吐与时延检查；首选直接部署训练得到的 Actor，不预设事后蒸馏。
- Actor 由 4070 上的独立 GPU HTTP 服务推理，具体比赛接入在部署验收后确定。它与 ADR-0009 为平台发布包选定的 CPU/ONNX 路径并存，不改写该契约。用户确认常见负载是同时 10 桌，部署测试覆盖持续请求与同步突发，端到端计时包含接收观察、排队、编码、推理与返回动作。P95 不超过 100 ms 是初始工程目标，不是用户确认的硬性协议；与棋力发生明显取舍时，呈现实测后再定。

## 实验证据

具体回执与报告在本项目 `.local/`（`scale-study/`、`overnight/`、`bc-curve/`）和仓库根 `.local/competition/runs/`，汇总在本机 `projects/personal/selfplay/.local/reports/guided-status.md`。

- **启动方式**：两台机器同规模各跑一组，A 从第一步联合训练 4 小时（初始 `w = 1`），B 先纯模仿 1 小时再联合训练 3 小时，教师示范生成计入预算；预先固定“B − A 配对区间下界大于 0 则选 B”。4090 的 384/8/8 为 [+11.75, +18.14]，4070 的 256/6/8 为 [+12.53, +19.25]，两种规模都选 B，因此采用模仿启动。A 从第一步就有教师辅助，所以这个差距不是“有无教师”的差距。
- **纯模仿时长**：两种规模都是约 40 分钟的快照平均成绩最好，60 分钟相对 40 分钟的区间跨零，最好版本仍落后冠军。暂以约 40 分钟作为模仿阶段候选时长；只有一个训练种子，且节点由同一批评估选出，定型前需在独立牌墙上复核。
- **模仿后的 PPO 收益**：十方大乱斗中 4070 的 B 相对其纯模仿对照有优势，去掉两个 A 的八方复赛没有重现；复赛中 B 与纯模仿、两种规模之间的比较区间都跨零，规则策略仍占前三。模仿后 3 小时 PPO 加教师辅助是否带来稳定增益尚无证据，这是正式主训练前要解决的主要问题。纯模仿对照是按原配置补训的独立模型，不是 B 的中途检查点。
- **模型规模**：15 分钟监督对照选了 384/8/8 作为首轮起点；此后的启动对照与两轮大乱斗没有显示 384/8/8 强于 256/6/8，两者在 4070 上的推理时延接近。规模尚未定型。
- **部署时延**：4070 上两种规模的 10 并发 P95 都未达到 100 ms 初始目标。该次测试所用冻结快照缺少编译的 `_fast` 扩展，观察编码走纯 Python 实现，比编译版慢一个数量级，结论需在补齐扩展后复测。

## 考虑过的替代方案

- 四路规则等权混合为监督教师：同一局面不同规则会给出冲突标签，学生仅凭标签无法判断哪个收益更高；用户选择主要模仿冠军，其余规则作为对手。
- 统一训练循环不设模仿阶段：启动方式对照中明显落后，已放弃。
- 独立 DAgger 阶段或 BC 棋力验收门槛：由联合训练中教师在学生访问状态上标注替代，减少阶段切换。
- 以显存容纳的最大模型为目标、事后蒸馏补部署预算：更大的模型每次决策与更新更贵，固定预算内未必更强；选型直接以 4070 部署表现约束，不依赖后续补救。
- 双机同步梯度或平均参数：首版不做，两机各自训练，只交换冻结产物，按同一条件择优。

## 工程默认值

以下是首轮可执行起点，不是实测最优值；数值以 `projects/personal/selfplay/guided/config.py` 为准，选型期可按显存与吞吐调整资源参数，不开展大规模超参数搜索。

- PPO：Actor 学习率 `1e-4`、clip `0.1`、最多两轮、目标 KL `0.01`、熵系数 `0.001`，`gamma = 1`、GAE `0.95`；约 `65536` 个学生决策为一次采样目标，完成在途整场后更新；有效批量 `512`，微批次、梯度累积与 worker 数按主机调整。每轮采样固定一个行为策略版本，不混入其他机器或其他代的样本。
- 指导：`D = 10` 桌面分/场，`lambda_max = 1.0`。监督项 90% 来自当前教师标注、10% 来自最多 `100000` 条的历史示范缓存；`w = 0` 时两者都为零，可跳过标签计算。
- 对手：每桌一个学习座位，其余三座为冻结对手，每座 75% 均匀抽成熟规则代表、25% 抽本路 RL 历史快照，池空时回给规则；历史池上限 16 份。两机初期不互相注入即时策略。
- 评估：例行师生评估双方各 1024 场、每场 16 局，约每两小时一次，不因成绩好坏动态增减场数。开发评估与最终测试使用独立随机命名空间，改变测试种子必须改变实际牌墙；最终测试目标每个参评版本 8192 场。用同一最终测试集择优时，明确它同时承担版本选择，胜者的单次区间不宣称无选择偏差。

# RL 线手册

先读[公共手册](common.md)。本手册只写 RL 线的差异，训练方案接口见 [recipes/API.md](../../selfplay/recipes/API.md)。

| 项目 | 内容 |
|---|---|
| 你改的目录 | `rl/recipe/` 的训练内容：算法、优势与目标、Critic、超参数。起点是 selfplay 基线方案的副本 |
| 模型 | 固定为最小规格 128/4/4（Actor 约 0.84M 参数），起点是它对 piao-call-channel 模仿 10 万局（每场 16 局）的结果。结构、观察编码和环境奖励由框架固定 |
| 训练预算 | 每次尝试 100 万局，没有时间上限，更慢的方案只是占主机更久（训练框架的 24 小时截止只防卡死）。实际训练局数超过预算 2.5 万局以上，尝试记为无效 |
| 执行与资源 | 三台主机的显存、内存、CPU 上限和训练速度各不相同，`status` 的「主机资源」列出每台的上限和最近一次训练的实际峰值与用时（设置在 `harness/rl.py` 的 `LIMITS` 与 `EXECUTION`）。采集的进程数、桌数和攒批时间按主机固定，方案给的 workers、tables 会被覆盖。训练时框架随时检查：进程组的进程数、显存占用、内存和 torch 线程数超出就立即结束，尝试记为崩溃 |
| 方案约定 | 训练局只通过 `ctx.collect` 打，方案不导入 `guided.collection`、`guided.environment` 这类会打局或跑任务的模块。start 先做静态检查，违规就不开跑 |
| 主机 | 4070、4090、5070 Ti 各是一个尝试位。wait 列出在线且空闲的主机，你选一台按它的资源设计，start 用 `--host` 指定；训练与评估都在那台主机上完成。训练 100 万局约 50～80 分钟，开发集 16384 场约 12～20 分钟，进入确认集再加差不多的时间 |
| 快照 | start 把 `rl/recipe/` 冻结到 `.local/rl/attempts/<编号>/recipe`，训练只用这份快照；wait 在设计前用最好版本的快照覆盖 `rl/recipe/` |
| 训练曲线 | 每次尝试结束后，逐步的训练指标（KL、Critic 拟合度、各段用时等）在 `.local/rl/attempts/<编号>/metrics.jsonl` |

## 三个尝试位

- 最初的最好版本是起点本身（`fp-rl-start-<池 id>`：模仿模型的成绩，方案快照是基线方案），三台主机从一开始就可以各朝一个方向改。基线方案原样训练也是一次正常的尝试。
- 三个尝试位共享一个最好版本。每个新尝试都从设计时的最好版本出发；先确认成功的成为最好版本，其他在途尝试随后改与新的最好版本比较。它们可能都基于旧版本，被取代的那处改动需要时再作为新尝试补上。
- 主机离线时，在途尝试等它回来接着做。主机重启丢了训练时，尝试用同一份快照排队，由任一空闲主机重做，排在新设计之前。这些都不算尝试的结果，也不需要你处理；wait 的【通知】会告诉用户主机的变化。
- 所有主机都不可用时，wait 一直是「等待」，照做就行。
- 按选定主机的资源定规模：显存宽裕的主机可以用更大的批量或常驻更多数据，慢的主机训练得更久。主机重启丢了训练时，重做可能落到另一台，所以显存、批量这类随资源变化的量从 `ctx.resources` 读取后换算，不要写死。分配器保留峰值贴着上限是正常的（它先缓存到上限，不够时再回收）；实际需要看张量峰值，两者差得多说明碎片多。

## 训练对手与教师

- 默认的训练对手是固定对手池（`ctx.opponents`，也是评估对手），默认教师是 piao-call-channel（`ctx.teacher`）。
- 可以换：`status` 的「可选训练对手与教师」列出固定对手池和两条线每一个成为过最好版本的版本（`ctx.catalog`），附固定对手池上的开发集成绩、每个决策的实测耗时和改动说明。两条线出了新的最好版本，下一次尝试开跑时就会出现在清单里。
- 在方案里选：`cfg["opponents"]` 从 `ctx.opponents` 与 `ctx.catalog` 里任选、可以混合，对手座位在列表里均匀抽取；`cfg["teacher"]` 从 `ctx.teachers` 里选一个规则。模型只能当对手，不能当教师。
- 代价只是时间：教师在每个学习决策上算一次，规则对手在自己的每个决策上算一次，按清单里的耗时估算会慢多少。
- 评估永远只对固定对手池，所以换对手和教师只改变训练，不改变比较口径。每次尝试开跑时的清单存档在 `.local/rl/attempts/<编号>/catalog.json`。

## 学习执行

方案配置里的 `resident_rows` 与 `gradient_graphs` 只改变学习步的执行方式，不改变采集量、模型、优势计算、Critic 拟合或 KL 更新口径，关掉它们可以做同工作量对照：

- `resident_rows`：在显存限额内让本轮学习输入按列常驻 GPU，供两折 Critic、Actor 梯度与 KL 检查复用；空间不足时沿用逐批搬运。
- `gradient_graphs`：在常驻输入上捕获 Actor 的取数、前向、反向与梯度累加，保持原始批次行数、历史长度和累加顺序；只捕获使用次数足够的形状，切换形状时释放用完的 Graph。

# RL 线手册

先读[公共手册](common.md)。本手册只写 RL 线的差异，训练方案接口见 [recipes/API.md](../../selfplay/recipes/API.md)。

| 项目 | 内容 |
|---|---|
| 你改的目录 | `rl/recipe/` 的训练内容：算法、优势与目标、Critic、超参数。起点是 selfplay 基线方案的副本 |
| 模型 | 规格按主机固定（维护者定）：4070 与 5070 Ti 是小规格 128/4/4（Actor 约 0.84M 参数），起点是它对 piao-call-channel 模仿 10 万局（每场 16 局）；4090 是中规格 256/6/8（约 4.8M 参数，2026-10-04 起，用户决定），起点是随机初始化的 random-medium-256x6，所以在 4090 上 `--from start` 就是从零训练。此前的大规格 384/8/8（约 14.3M 参数）版本仍可在开发集上比较，但没有主机再训练它们。结构、观察编码和环境奖励由框架固定。各种规格打同一个开发集、共享一个最好版本，成绩直接可比 |
| 训练局数 | 每次尝试由你定：start 加 `--hands N`，默认 100 万局。小规格与中规格最多 500 万局，带教师标签的局数不另设上限；大规格（已无主机训练）最多 1000 万局，其中带教师标签的（模仿、蒸馏）最多 500 万局，框架在 `ctx.labeled_hands_left()` 里给出剩余量，用完后再带标签采集会报错。大规格分段训练：一段就是一次尝试，下一段用 `--from <上一段的版本编号>` 接着训练，每段都评估，所以中途每段都有成绩可看、可以随时调整方向；训练量沿路径累积，不设累计上限。现在的方案里 PG 每步直接在 KL 约束下更新 Actor、Critic 每轮重新拟合，没有跨步的优化器状态，所以分段续训与一次跑完等价（续训只传 Actor；方案若加了跨段的状态，要自己在续训时重建）。局数越多，一次尝试占主机越久，三个尝试位一天出的结果越少；大规格比小规格慢约 3～4 倍，按 `status` 主机资源里最近一次训练的用时和 `metrics.jsonl` 的逐步用时估算（带教师标注的蒸馏批比 RL 批慢得多）。没有时间上限（训练框架的 48 小时截止只防卡死）。实际训练局数超过你定的局数 2.5 万局以上，尝试记为无效 |
| 起点 | 默认从所选主机的固定起点训练（规格随主机）。续训只能在同规格版本之间：`--from best` 或 `--from <版本编号>` 指向另一种规格的版本时，start 会拒绝。start 加 `--from best` 从你设计时的最好版本接着训练；`--from <版本编号>` 从任意一个评估过的 RL 版本出发，成功与否都行（例如某次只做模仿的结果）；方案也可以不用给定的 Actor，用 `ctx.new_actor()` 从随机初始化开始（例如换一个教师从头模仿）。训练量沿出发的那条路径累积，汇报和 `status` 显示累计局数。所以起点本身也在你的行动空间里：可以只做到模仿就结束这次尝试、拿它和原来的起点比，下一次再从它出发做 RL；局数按这一段实际需要定。要成为最好版本，仍要在开发集和确认集上超过最好版本。从已学过教师的版本出发时，要不要再蒸馏、蒸馏多少，按起点设计 |
| 比较 | 当前对手池下评估过的任意两个版本都能直接比：`python -m harness.evaluate compare <A> <B>` 用两者存档的开发集逐组得分配对，给出差值、误差和单侧 90% 下界，不用再打。事先定好的两两对照（例如新旧两种模仿）直接看它；从许多尝试里挑出的最高者会偏高，以确认集为准 |
| 执行与资源 | 三台主机的显存、内存、CPU 上限和训练速度各不相同，`status` 的「主机资源」列出每台的上限和最近一次训练的实际峰值与用时（设置在 `harness/rl.py` 的 `LIMITS` 与 `EXECUTION`）。采集的进程数、桌数和攒批时间按主机固定，方案给的 workers、tables 会被覆盖。训练时框架随时检查：进程组的进程数、显存占用、内存和 torch 线程数超出就立即结束，尝试记为崩溃 |
| 方案约定 | 训练局只通过 `ctx.collect` 打，方案不导入 `guided.collection`、`guided.environment` 这类会打局或跑任务的模块。start 先做静态检查，违规就不开跑 |
| 主机 | 4070、4090、5070 Ti 各是一个尝试位，4070 与 5070 Ti 跑小规格，4090 跑中规格。主机重启丢了训练时，尝试只排队给同规格的主机重做。wait 列出在线且空闲的主机，你选一台按它的资源设计，start 用 `--host` 指定；训练与评估都在那台主机上完成，评估用时见汇报 |
| 快照 | start 把 `rl/recipe/` 冻结到 `.local/rl/attempts/<编号>/recipe`，训练只用这份快照；wait 在设计前用最好版本的快照覆盖 `rl/recipe/` |
| 训练曲线 | 每次尝试结束后，逐步的训练指标（KL、Critic 拟合度、各段用时等）在 `.local/rl/attempts/<编号>/metrics.jsonl` |

## 规模训练（维护者，2026-10-03 已结束）

以下是当时的约定，留作阅读旧记录的参考。

维护者在 4090 上跑一次固定的大规格规模训练，训练对手是第三代训练对手、评估照常对固定对手池（[ADR-0016](../../../../docs/adr/0016-maintainer-iteration-lines.md) 2026-09-30 修订）：从随机初始化开始模仿 500 万局，再做 1 亿局 RL，分成 12 段，每段都是 RL 线的一次尝试，描述以「规模训练第 k/12 段（维护者，固定方案）」开头。它们照常评估、汇报，超过最好版本就确认，确认成功就成为最好版本。

- 不是你开跑的，不必设计它们，也不要取消；汇报里的结论照常写进迭代笔记，可以当作大规格随训练量变化的证据。
- 某段成为最好版本后，wait 恢复的本线目录就是规模训练方案（`scale/recipe` 的副本，不带它在规模训练里的段号），此时它按 PG 阶段的开头运行。小规格主机不能从大规格的最好版本续训：用 `--from <某个小规格版本>`，或从起点、从随机初始化开始。

## 三个尝试位

- 最初的最好版本是起点本身（`fp-rl-start-<池 id>`：模仿模型的成绩，方案快照是基线方案），三台主机从一开始就可以各朝一个方向改。基线方案原样训练也是一次正常的尝试。
- 三个尝试位共享一个最好版本。每个新尝试都从设计时的最好版本出发；先确认成功的成为最好版本，其他在途尝试随后改与新的最好版本比较。它们可能都基于旧版本，被取代的那处改动需要时再作为新尝试补上。
- 主机离线时，在途尝试等它回来接着做。主机重启丢了训练时，尝试用同一份快照排队，由任一空闲主机重做，排在新设计之前。这些都不算尝试的结果，也不需要你处理；wait 的【通知】会告诉用户主机的变化。
- 所有主机都不可用时，wait 一直是「等待」，照做就行。
- 按选定主机的资源定规模：显存宽裕的主机可以用更大的批量或常驻更多数据，慢的主机训练得更久。主机重启丢了训练时，重做可能落到另一台，所以显存、批量这类随资源变化的量从 `ctx.resources` 读取后换算，不要写死。分配器保留峰值贴着上限是正常的（它先缓存到上限，不够时再回收）；实际需要看张量峰值，两者差得多说明碎片多。

## 训练对手与教师

- 默认的训练对手是固定对手池（`ctx.opponents`，也是评估对手），默认教师是 piao-call-channel（`ctx.teacher`）。
- 可以换：`status` 的「可选训练对手与教师」列出固定对手池和两条线每一个成为过最好版本的版本（`ctx.catalog`），附固定对手池上的开发集成绩、每个决策的实测耗时和改动说明。两条线出了新的最好版本，下一次尝试开跑时就会出现在清单里。
- 清单里有维护者登记的第三代训练对手（`fp68-classic`、`fp68-flat`、`fp68-kong-eager`、`fp68-peng-speed`、`fp68-chi-speed`、`fp68-closed-early`、`fp68-patient-big`）：7 种风格都从规则线 fp-rule-068 派生，比固定对手池强得多（在它的开发集上 +2.3～+5.7），是 C 实现，可以和固定对手池一样走整局 C 的快速采集，但每个决策慢约 8 倍，采集会慢到约三分之一。它们只用于训练，评估仍对固定对手池。
- 清单里还有维护者登记的平台代理对手（`proxy-p01` … `proxy-p30`、`proxy-tail`）：每个是一位线上常见玩家的模仿模型（小规格，按最大概率出牌），`proxy-tail` 是其余玩家的合成。它们的动作风格与本人吻合（每位玩家的留出局面上都是自己的代理猜得最准），强弱还原得不好（与本人线上强弱的相关约 0.4）。只能当训练对手，不能当教师；评估对手池不变。
- 在方案里选：`cfg["opponents"]` 从 `ctx.opponents` 与 `ctx.catalog` 里任选、可以混合，对手座位在列表里均匀抽取；`cfg["teacher"]` 从 `ctx.teachers` 里选一个规则或 RL 线版本。模型教师的标签是它在合法动作上的 argmax，由采集父进程与学生同批推理，对局照常走 C 引擎，比规则教师快得多；`cfg["teacher_plays"] = True` 时学习座位直接走教师的动作（行为克隆），否则学生自己出牌、教师只打标签（DAgger）。
- 清单里也有 RL 线自己每一个成为过最好版本的 Actor。拿它们当训练对手就是和过去的自己对打（联赛式自我对弈），训练出的打法不只针对固定对手池；也可以和规则版本、固定对手池混着用。
- 代价只是时间：教师在每个学习决策上算一次，规则对手在自己的每个决策上算一次，按清单里的耗时估算会慢多少。
- 评估永远只对固定对手池，所以换对手和教师只改变训练，不改变比较口径。每次尝试开跑时的清单存档在 `.local/rl/attempts/<编号>/catalog.json`。

## 学习执行

方案配置里的 `resident_rows` 与 `gradient_graphs` 只改变学习步的执行方式，不改变采集量、模型、优势计算、Critic 拟合或 KL 更新口径，关掉它们可以做同工作量对照：

- `resident_rows`：在显存限额内让本轮学习输入按列常驻 GPU，供两折 Critic、Actor 梯度与 KL 检查复用；空间不足时沿用逐批搬运。
- `gradient_graphs`：在常驻输入上捕获 Actor 的取数、前向、反向与梯度累加，保持原始批次行数、历史长度和累加顺序；只捕获使用次数足够的形状，切换形状时释放用完的 Graph。

# 规则线手册

先读[公共手册](common.md)。本手册只写规则线的差异，杭州麻将规则与计分见[平台规则](../../../../docs/reference/platform.md)。

| 项目 | 内容 |
|---|---|
| 你改的目录 | `rule/`（主要是 `rule/strategy.py`）。v0 是最朴素的牌效策略，只看向听和进张 |
| 目标 | 从规则的第一性原理出发，覆盖全部观察和动作空间，做出尽可能强的规则策略。大方向是速度优先、必胜时追求翻倍，整体上不防守。自动研究的分支都从同一个初始策略演化而来，视野偏窄；这条线要有意尝试它们没用过的观察和动作。对手池成员的源码可以参考，但不照搬 |
| 时限 | 策略的算力不设上限，但正式比赛是多桌并发，出牌 2.0 秒、应答 0.6 秒不能超。超时由平台默认动作代打，代价直接算进分数 |
| 主机 | Mac 本机评估，同一时间一个尝试。开发集 16384 场约 30 分钟（对手池里的大模型在 MPS 上推理是瓶颈），进入确认集再加约 30 分钟 |
| 快照 | start 把 `rule/` 冻结到 `.local/attempts/<编号>/package`，评估只用这份快照；wait 在设计前用最好版本的快照覆盖 `rule/` |

第一次尝试就是 v0 原样。它没有可比的版本，打完开发集后直接成为规则线的最好版本。

## 自由对战上场版本

自由对战由常驻脚本 `.local/competition/free_play_strongest.py` 负责，上场版本写在 `.local/competition/entrant.pin`。两条线的每个新的最好版本，都会在汇报里对照当前上场版本（开发集上的配对差）。标出「高于参照线，可以上场」时，wait 会让你停下问用户；用户同意后运行 `promote <编号>`，常驻脚本在下一房开始时换上。
